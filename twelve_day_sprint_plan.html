Phase 1 Foundation + knowledge base (Day 1–3)
D1
Repo scaffold — folder structure, pyproject.toml, CaseRecord pydantic model, docker-compose (local Neo4j + Azurite)
Terraform layers 1–3 — Resource group, VNet, subnets, Storage account + containers, Key Vault
GitHub repo + CI skeleton — branch rules, Actions workflow (lint + type-check on push), .env.template
D2
CMS XML parser — parse ICD-10 tabular XML into node/edge dicts for Neo4j (chapters, codes, excludes1/2, code-first)
Terraform layers 4–5 — Cognitive Services (Doc Intel + OpenAI), AI Search, Functions App, App Service plan
Neo4j provisioning script — Docker on VM or AKS manifest, Bolt URI into Key Vault, test connectivity
D3
Guidelines chunker + search indexer — chunk PDF by section, metadata tags (section_id, chapter, rule_type), push to AI Search
Private endpoints + NSGs — lock down Neo4j, Storage, Search, OpenAI to VNet only. Hand off .env.template to team
KB build pipeline — GitHub Action that runs XML parser + chunker + indexer end-to-end. Wire to dev env
Gate 1 Neo4j has all 22 chapters. AI Search returns chunks. Everyone can run locally + connect to Azure dev
Phase 2 Rules engine + pipeline stages 1–7 (Day 4–7)
D4
Stages 1–2 — intake (file upload handler), ingest (Document Intelligence OCR+NER wrapper), output structured facts into CaseRecord
Managed identity RBAC — Functions → Storage, Search, OpenAI, Key Vault. Zero secrets in code
Per-stage deploy pipeline — CD that deploys only changed function stages. pytest integration in CI gate
D5
Stage 3 + rules engine core — extract/classify encounter, Neo4j lookups. Build conventions.py, excludes_checker.py, chapter_mandates.py
OpenAI deployment tuning — GPT-4o model version, TPM quota, content filter config. Test endpoint from Functions
Audit trail writer — helper that writes stage artifacts to blob. Path convention: audit-trail/{case_id}/stage_N.json
D6
Stage 4 (hard elimination) — Excludes1 = hard kill, Excludes2 = flag, Code First / Use Additional = sequence mandate. Stage 5 — guideline retrieval (chapter-filtered AI Search query)
AI Foundry workspace — link to Functions, configure evaluation metrics (hallucination rate, citation accuracy, escalation rate)
Test data creation — 5 synthetic medical charts (PDFs) + candidate lists covering Section II rules A, B, C, G, H, K
D7
Stage 6 (LLM sequencer) — prompt template, structured JSON output, hallucination guard (output ⊆ candidates). Stage 7 — Section II A–K offline validator
Integration testing — full pipeline from blob upload → sequenced output on dev environment. Fix config issues
Eval harness — CI job that runs gold-standard test cases, reports pass/fail. Prompt versioning via git tags
Gate 2 Upload a test PDF → get sequenced diagnoses with citations. Eval harness runs green. Audit trail in blob
Phase 3 Demo UX + coder review + integration (Day 8–10)
D8
Demo UX frontend — upload chart + candidates → show sequenced output with per-position citations, collapsible audit trail
App Service deployment — deploy UX, configure custom domain/TLS if needed, App Insights dashboards
Staging environment — terraform apply staging.tfvars, deploy all stages, run eval suite against staging
D9
Stage 8 (coder review UI) — accept/reorder/override with logged reason. Stage 9 — final output assembly with audit links
Monitoring dashboard — per-stage latency, error rate, LLM token usage, coder override rate
Demo env promotion — terraform apply demo.tfvars, smoke tests, post-deploy validation suite
D10
End-to-end polish — fix bugs from integration, improve error handling, edge case coverage in rules engine
Cost analysis — SKU sizing doc, monthly Azure cost estimate, scaling recommendations
Operational runbook — incident response, rollback procedures, secret rotation, KB refresh process
Gate 3 Demo UX works end-to-end on demo env. Coder can override. Full audit trail. Monitoring live
Phase 4 Deliverables + demo prep (Day 11–12)
D11
Solution design doc — architecture decisions, AI governance section, hallucination mitigation, evaluation strategy
Deployment guide — step-by-step terraform runbook, env setup, pre-reqs, another team can follow
Lessons learned doc — what worked, what didn't, reusability assessment, what to do differently
D12
Demo script + rehearsal — prepare show & tell narrative, walk through 2 scenarios live, rehearse as team
Architecture diagram — final polished version matching actual deployed state, proposal-ready format
Final tag + README — release tag, clean README with quickstart, verify all deliverables committed
