# 3-Day Interview Prep Plan — Lead Engineer I, Cigna Healthcare (Azure GenAI, ~4 YOE)

## TL;DR
- Build your 3 days around what payer-healthcare interviewers actually test at Lead-I level: **(Day 1)** retrieval engineering + Azure AI Search + your PDV project story; **(Day 2)** agents (Microsoft Agent Framework + LangGraph) + MCP + spec-driven dev + evals; **(Day 3)** PHI-safe architecture, CI/CD, data pipelines, C#/.NET and healthcare interop. Every module runs Basics → Medium → Advanced with likely interview questions.
- The version-dependent facts you must get right in 2026: **Azure AI Foundry is now "Microsoft Foundry"** (renamed at Ignite Nov 18 2025, formalized in the Jan 2026 Product Terms); **Microsoft Agent Framework (MAF) reached 1.0 GA on April 3, 2026** (`pip install agent-framework` / NuGet `Microsoft.Agents.AI`), superseding Semantic Kernel + AutoGen; **Prompt Flow is being retired April 20, 2027** (Microsoft points you to MAF); **the eval SDK is `azure-ai-evaluation`**; **MCP's stable spec is 2025-11-25 with a 2026-07-28 release candidate**; **AI-102 retired June 30, 2026 and was replaced by AI-103**.
- Your PDV project is strong interview capital but carries three landmines you must pre-empt: (1) PDV *rejected* multi-agent debate while the JD explicitly asks for multi-agent orchestration; (2) PDV sends chart text to LLMs while the JD says "no PHI in prompts"; (3) salted SHA-256 of low-entropy identifiers (MRN, ICD codes) is reversible by brute force — say keyed HMAC-SHA-256 or tokenization instead.

**Azure AI Search.** Hybrid search fuses BM25 + vector via **Reciprocal Rank Fusion (RRF)**. **Semantic ranker** reranks only the **top 50** results from the first-pass (BM25/RRF) set, using models from Bing/Microsoft Research; [Azure Docs](https://docs.azure.cn/en-us/search/semantic-search-overview) summary strings up to **2,048 tokens** (raised from 256 in Nov 2024); [Microsoft Learn](https://learn.microsoft.com/en-us/azure/search/semantic-search-overview) rerankerScore 0–4; premium add-on, not on Free tier (Basic tier and up). [Microsoft Learn](https://learn.microsoft.com/en-us/azure/search/semantic-search-overview) [OneUptime](https://oneuptime.com/blog/post/2026-02-16-how-to-implement-semantic-ranking-in-azure-ai-search-for-better-relevance/view) **Agentic retrieval** (LLM query decomposition → parallel subqueries → per-subquery hybrid + semantic rerank top-50 → merged unified response with citations + activity log) is exposed via the **Knowledge Base** object (2025-11-01-preview API; [DEV Community](https://dev.to/suhas_mallesh/azure-ai-search-advanced-rag-with-terraform-hybrid-search-semantic-ranking-and-agentic-retrieval-180k) **"Knowledge Agent" was renamed to "Knowledge Base"** [Microsoft Developer Blogs](https://devblogs.microsoft.com/azure-sdk/azure-sdk-release-january-2026/) in the Jan 2026 SDK). It underpins **Foundry IQ**, the managed knowledge layer. Classic RAG (hybrid + semantic) is the GA path; agentic retrieval is the preview/advanced path. [Microsoft Learn](https://learn.microsoft.com/en-us/azure/search/retrieval-augmented-generation-overview) (Sources: Microsoft Learn semantic-search-overview, agentic-retrieval-overview, retrieval-augmented-generation-overview; Azure SDK Jan 2026 release blog.)

## Details — The 3-Day Plan (ordered by interview value, ~5–6 hrs/day)

### DAY 1 — Retrieval engineering + Azure AI Search + PDV story (highest interview value)

**Module 1.1 — RAG fundamentals & chunking/embeddings.**
*Basics:* RAG grounds an LLM in your proprietary data by retrieving relevant chunks at query time and injecting them into the prompt; it solves hallucination, staleness, and the context-window limit, and provides citations. It sits between your data store and the LLM.
*Medium:* Ingestion = load → chunk → embed → index. Chunking: fixed-size with overlap (e.g., ~512 tokens, 10–15% overlap), semantic/recursive, and structure-aware (headings, tables). Embeddings: `text-embedding-3-large` (3,072 dims, truncatable) vs `-3-small` (1,536). Store vector + text + metadata together for hybrid + filtering.
*Advanced:* Failure modes — chunk too large (dilutes relevance, wastes tokens), too small (loses context), bad overlap (duplicate hits), embedding-model drift (re-embed the whole corpus when you change models — never mix embedding spaces). Ideal: hybrid retrieval + reranking + metadata filters + citation enforcement. Interview Qs: "Walk me through your ingestion pipeline and why you chose your chunk size" (checking: empirical reasoning vs cargo-cult); "You change embedding models — what breaks?" (checking: you know you must re-index everything); "How do you evaluate retrieval quality separately from generation?" (checking: recall@k, NDCG vs groundedness).

**Module 1.2 — Azure AI Search deep dive.**
*Basics:* Managed search/retrieval engine — indexes, BM25 keyword, vector (HNSW default), and hybrid.
*Medium:* Hybrid = BM25 + vector fused by **RRF**. **Semantic ranker** reranks the **top 50** first-pass results (rerankerScore 0–4, summaries up to 2,048 tokens), a premium add-on on Basic tier and up. [Azure Docs](https://docs.azure.cn/en-us/search/semantic-search-overview) [Microsoft Learn](https://learn.microsoft.com/en-us/azure/search/semantic-how-to-query-request) Integrated vectorization embeds at index and query time. Index aliases enable zero-downtime reindexing.
*Advanced:* **Agentic retrieval / Knowledge Base** (renamed from Knowledge Agent, Jan 2026) decomposes complex queries into parallel subqueries, each hybrid+reranked, merged with citations — preview, adds latency but improves multi-intent answers; [DEV Community](https://dev.to/suhas_mallesh/azure-ai-search-advanced-rag-with-terraform-hybrid-search-semantic-ranking-and-agentic-retrieval-180k) underpins Foundry IQ. Tradeoffs: semantic ranker adds latency/cost but big relevance gains on prose; vector-only misses exact-match terms (codes, IDs) — critical for ICD codes, so hybrid is mandatory in healthcare. Vector quantization/compression reduces index size at a small recall cost. Interview Qs: "Vector-only vs hybrid for a medical-coding corpus?" (checking: you know exact code strings need BM25); "How does the semantic ranker actually work, and its cost/latency profile?"; "Design security trimming so a user only sees permitted documents" (checking: filter-based document access control).

**Module 1.3 — Tie in PDV (your headline project).** Rehearse a 90-second architecture narrative: Document Intelligence OCR → chunk coding guidelines → `text-embedding-3-large` into **Cosmos DB NoSQL vector store (DiskANN)** + **Neo4j** for ICD-10 rules (Excludes1, Code First, billability) → Foundry agents (GPT-4.1, Claude Sonnet) → deterministic candidate-membership guard → human-in-the-loop coder portal. Emphasize the **guard that replaced the LLM-as-judge** after it approved hallucinated code "A01.01" — your best "judgment over hype" story. (Landmines handled below.)

### DAY 2 — Agents (MAF + LangGraph), MCP, spec-driven dev, evals

**Module 2.1 — Microsoft Agent Framework.**
*Basics:* MAF is Microsoft's unified, GA (Apr 3, 2026) agent SDK replacing Semantic Kernel + AutoGen; it builds/orchestrates agents in Python (`agent-framework`) and .NET (`Microsoft.Agents.AI`).
*Medium:* `AIAgent`/`ChatClientAgent` wrap a chat client; `AgentThread` holds conversation state (agents are stateless). **Workflows** = graph orchestration (executors/nodes, edges, branching, fan-out, checkpointing/hydration). **Orchestration patterns**: sequential, concurrent, group chat, handoff, Magentic. Integrates with Foundry Agent Service; OpenTelemetry tracing built in.
*Advanced:* vs LangGraph — MAF is the native Azure/.NET choice with first-party Foundry integration but young (GA Apr 2026, less production hardening); LangGraph v1.0 (Oct 2025) has a year-plus of production use (Uber, LinkedIn, Klarna). [Medium](https://medium.com/@maneeshkumar52/microsoft-agent-framework-autogen-semantic-kernel-finally-merged-b9b3f17cf09c) For a Microsoft-standardized payer shop, MAF is the strategic bet; LangGraph is the battle-tested pragmatic choice. Interview Qs: "MAF vs LangGraph for our stack — which and why?" (checking: you weigh maturity vs integration, not fanboy); "How does MAF relate to Semantic Kernel/AutoGen?"; "When do you use a deterministic workflow vs an autonomous multi-agent pattern?" (checking: you prefer determinism where correctness matters — your PDV thesis).

**Module 2.2 — LangGraph.** Basics/Medium/Advanced per Key Findings: StateGraph + reducers, checkpointers, `interrupt()` for HITL (use `interrupt_before`), supervisor/handoff. Interview Q: "Design a human-approval gate that never executes the action before approval" (checking: `interrupt_before` + a checkpointer).

**Module 2.3 — MCP.**
*Basics:* Open protocol (the "USB-C for AI tools") standardizing how LLM apps connect to tools/data; stable spec **2025-11-25**, RC **2026-07-28**.
*Medium:* Transports stdio (local) and Streamable HTTP (remote). Primitives: tools, resources, prompts, sampling, elicitation, roots, Tasks. Author with Python FastMCP or C# `ModelContextProtocol.AspNetCore`. Host on Azure Functions (MCP extension or self-hosted preview), Container Apps; register in Azure API Center; gateway via APIM.
*Advanced:* Auth = OAuth 2.1 Resource Server + RFC 8707 Resource Indicators; token passthrough forbidden. Security risks — tool poisoning, confused deputy, prompt injection; mitigate with HITL approval, audience-bound least-privilege tokens, tool pinning. Interview Qs: "How do you secure a remote MCP server handling PHI?" (checking: managed identity/Entra, private endpoints, no token passthrough, no PHI in tool args); "Author an MCP server exposing your ICD rule engine — what are the tools/resources?"

**Module 2.4 — Spec-driven dev & verifying AI code.** Spec Kit flow constitution→specify→plan→tasks→implement; Copilot agent mode; copilot-instructions.md/AGENTS.md. Best practice for verifying AI code: tests-first, small verifiable increments, human review gates, eval gates, static analysis/scanning. Interview Q: "How do you trust AI-generated code in a HIPAA system?" (checking: you never merge unreviewed AI output; deterministic tests + human sign-off).

**Module 2.5 — Evaluation harnesses.** `azure-ai-evaluation`: `evaluate()` API, groundedness/relevance/retrieval + agent evaluators (intent resolution, tool call accuracy, task adherence), custom evaluators, golden datasets, cloud eval, red teaming (PyRIT). [Microsoft Learn](https://learn.microsoft.com/en-us/azure/foundry/concepts/observability) Prompt Flow retiring Apr 20 2027 → MAF. Ideal: golden regression set (PHI-free), eval gate in CI that blocks merge if groundedness/tool-accuracy regress. Interview Qs: "What's in your golden dataset and how do you keep PHI out?"; "LLM-as-judge failed you — what did you do?" (your candidate-membership guard story).

### DAY 3 — PHI-safe architecture, CI/CD, data pipelines, C#/.NET, interop

**Module 3.1 — PHI-safe engineering.** HIPAA basics (PHI, 18 Safe Harbor identifiers, BAA, minimum necessary). Azure OpenAI HIPAA-eligible for text under BAA; no training on your data. ## Reference: Ideal CI/CD for an Azure GenAI/RAG/agent app (2026)
Use **GitHub Actions or Azure DevOps** with **workload identity federation (OIDC)** — no stored cloud secrets. **Build once, promote the same artifact** across dev→test→prod; **tag container images by git SHA**; scan images (Trivy/Defender) and fail on criticals. IaC via **Bicep or Terraform** using **Azure Verified Modules**. Pipeline stages: lint/unit → build+scan image → deploy to dev → **eval gate** (run `azure-ai-evaluation` golden set; block on groundedness/tool-accuracy regression) → **canary via Container Apps revisions** (traffic split 10%→100%) → prod with automated rollback (shift traffic to the last good revision). Version prompts, model deployment names/versions, and the search index (via aliases) as first-class artifacts. Pin model versions (disable auto-upgrade) so evals stay reproducible.

## Reference: Ideal repo structure
Monorepo-ish layout: `/src` (app, agents, tools/mcp servers), `/ingestion` (pipeline functions), `/infra` (Bicep/Terraform AVM), `/evals` (golden datasets — PHI-free, custom evaluators), `/prompts` (versioned templates), `/tests`, `/.github` or `/pipelines`, plus `copilot-instructions.md` / `AGENTS.md`, `constitution.md` (Spec Kit), and a `specs/` tree. Secrets in Key Vault; config via managed identity.

## Reference: Ideal event-driven RAG ingestion pipeline
Blob/ADLS Gen2 upload → **Event Grid** event → Azure Function (Flex Consumption) or Container App job → OCR (Document Intelligence) → chunk → embed → upsert to vector store. Make it **idempotent** (hash document content → deterministic doc IDs; skip unchanged). **Dead-letter** failures to a Service Bus/Storage queue with retry + poison handling. Handle **deletions** (tombstone events → delete vectors). Handle **re-embedding** (version your embedding model; a model change triggers a full re-index behind an index alias). Use **Service Bus** for ordered/transactional work, **Event Grid** for reactive fan-out, **Event Hubs** for high-throughput streaming.

## Reference architecture: production Azure GenAI healthcare app
Front door: APIM AI gateway (token-limit policy, semantic caching, load-balance/circuit-break across PTU + PAYG backends) [Microsoft Learn](https://learn.microsoft.com/en-us/azure/architecture/ai-ml/guide/azure-openai-gateway-multi-backend) → app on Container Apps (managed identity, private endpoints, VNet) → orchestration (MAF or LangGraph) → retrieval (Azure AI Search hybrid+semantic and/or Cosmos DB DiskANN; Neo4j for graph rules) → Azure OpenAI (Global Standard or Data Zone for residency) under BAA → Key Vault for secrets → App Insights/Azure Monitor + Foundry tracing (content capture OFF) → de-identification (Health Data Services/Presidio) before any prompt → human-in-the-loop review portal. Ingestion via Event Grid + Functions as above. FHIR service for interop.

## Three system-design prompts (payer/Cigna), with outline answers
**1) "Design a GenAI prior-authorization assistant for CMS-0057-F."** Outline: FHIR R4 Prior Authorization (PARDD) API ingest → de-identify → retrieve payer policy (hybrid AI Search) + member coverage (FHIR) → agent drafts determination with citations → deterministic rules guard → human clinician approval (72-hr urgent / 7-day standard SLA) → structured denial reasons → audit trail. Emphasize no PHI in prompts (de-id + minimum necessary), eval gates, and that the LLM assists, never auto-denies.
**2) "Design a RAG system over clinical coding guidelines that must never fabricate codes."** Outline: your PDV pattern — hybrid retrieval, candidate-membership deterministic guard, graph rules in Neo4j, groundedness evals, HITL. Stress exact-match (BM25) for codes.
**3) "Design a multi-agent claims-document processing pipeline at scale."** Outline: Event Grid + Functions ingestion, Document Intelligence, MAF workflow (deterministic graph) with specialist agents (extract, validate, summarize), MCP tools for internal systems, checkpointing for durability, dead-lettering, APIM gateway for cost control, PHI de-id throughout.

## Tying in PDV — landmines and how to answer
1. **Multi-agent gap:** JD wants multi-agent orchestration; PDV deliberately rejected multi-agent debate. Answer: "We chose a deterministic workflow with a single reasoning agent plus a deterministic guard because in coding, correctness beats emergent behavior — multi-agent debate increased variance without improving accuracy. I understand MAF's group-chat/handoff/Magentic patterns and would use them where tasks genuinely decompose (e.g., separate extraction/validation/summarization agents in a claims pipeline)." Turns a gap into judgment.
2. **PHI-in-prompts contradiction:** PDV sends chart text to LLMs; JD says no PHI in prompts. Answer: acknowledge honestly — "Under our BAA, Azure OpenAI text is HIPAA-eligible and doesn't train on our data, so chart text in prompts was permitted for the pilot. The stricter target state is de-identification before prompting (Presidio / Health Data Services de-id) and keeping PHI out of logs/traces/eval sets — which is where I'd take it."
3. **Salted SHA-256 weakness:** low-entropy identifiers are brute-forceable. Answer: "Salted SHA-256 in telemetry was a mitigation, but MRNs/codes have low entropy, so a known-salt brute force reverses them. The right approach is keyed HMAC-SHA-256 with the key in Key Vault, or tokenization via a vault — and ideally not emitting the identifier at all."
